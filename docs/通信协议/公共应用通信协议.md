# 公共应用通信协议

## 1. 合同范围与采用方式

本文唯一维护公共应用消息的完整字节编码。客户使用边界、控制联系、快照解释及维护结果由[SDK README](../../README.md#公共交互与结果)维护；直接 CAN 接入另见[CAN 接入指南](../../CAN接入指南.md)。

[CAN 绑定](CAN通信绑定.md)与[USB 绑定](USB通信绑定.md)去掉各自封装、填充并完成重组后，交付本文定义的同一字节串。相同业务消息不因 Classic、FD 或 USB 使用不同数值精度、字段子集或配置格式。编解码只处理表示；实际入口由接收方附加，不来自请求字段。编解码不执行控制、保护、维护准入、保存或恢复，不持有硬件资源。

采用固定头、按类型确定的紧凑载荷和完整消息 CRC。短目标不使用通用属性字典、可选参数补全或业务请求号；配置使用配置所有者的完整 JSON。这样避免另一套配置字段布局，并让跨语言消费者直接按偏移实现。

## 2. 完整消息与基本表示

所有偏移从零开始，长度单位为字节；`u8/u16/u32/u64` 是相应宽度的无符号整数，多字节整数和浮点位模式均为小端。表中的顺序串接，不作内存对齐，不隐含长度或填充。`bytes[n]` 恰有 n 字节。

| 整条消息偏移 | 长度 | 字段 | 规则 |
|---|---:|---|---|
| 0 | 1 | `version` | `01`；这是公共线上版本，独立于软件版本、配置格式及 USB 描述符版本 |
| 1 | 1 | `type` | 第3节定义的消息类型 |
| 2 | 2 | `payload_length` | 载荷长度 P；不含头或 CRC，`0..16432` |
| 4 | P | `payload` | 恰好满足该消息类型的布局 |
| 4+P | 4 | `crc32c` | 对偏移 `[0,4+P)` 的 CRC-32C，结果小端 |

完整消息长度 `L=P+8`，最小 8，最大 **16440**。最大值容纳一份 16384 字节配置和完整读回元数据。不同版本不协商兼容，不从字段相似性推断可以解码。字段增加、单位或表示改变、现有类型长度改变都必须使用新的公共版本；当前版本未分配的类型和枚举值为保留值，不是可自行扩展的业务接口。

CRC-32C 参数：宽度32，多项式 `0x1EDC6F41`，反射实现使用 `0x82F63B78`，初值 `0xFFFFFFFF`，输入和输出反射，最终异或 `0xFFFFFFFF`；`"123456789"` 的结果为 `0xE3069283`。不含 CAN ID、传输块头、填充和 USB 定界字节。CRC 用于发现损坏和错误组合，不是身份认证、防恶意重放或绝对无碰撞证明。

`f32` 为 IEEE 754 binary32；允许有限值、次正规数和正负零，数值域为约 ±3.402823466×10³⁸，最小正次正规数约1.401298464×10⁻⁴⁵。线上没有 NaN/Infinity 业务值。接收器拒绝任何指数位全1的浮点字段；不能饱和、转零或沿用旧值。正负零在业务上等价。主机从其他数值类型转换时先检查有限性与可表示性；精度按 binary32 舍入，不能宣称十进制原值完全无损。

所有字段必填；可选内容只能按明确的判别字段省略。保留字节和未分配位发送为0、接收非0则拒绝。字符串用 `u8` 字节长度后跟对应数量 UTF-8 字节，无 NUL 终止、BOM 或隐含补齐；必须是有效 UTF-8，不允许嵌入 NUL。字符串上限见所属字段，空串只用于明确不可取得的值。原始配置读回的 `bytes` 不要求 UTF-8 或可解析 JSON。

### 2.1 唯一的头部判断与完整校验

前缀判断与完整解码共用以下定义，不能在传输层重新解释类型长度：

1. 不足4字节为“头未完整”，不得访问长度字段之外的内容。
2. 验证版本、类型是否已定义及该类型是否允许此接收方向；验证 P 在全局上限和第3节相应固定长度或变长上下限内。失败为“格式非法”，不是零长消息或待收更多。
3. 合法头确定唯一 L。前缀判断只能给出所需长度，不表示载荷已合法。
4. 完整解码只接收恰好 L 字节，验证 CRC、所有字段的判别值、嵌套长度、保留零和数值表示；变长结构必须恰好耗尽 P。多余尾部也非法。
5. 通过上述检查才交付完整消息。目标是否在业务允许域、维护是否获准等由业务所有者判断。配置字节仅受本层长度约束，完整解析和目标类型表示检查交给 `config`，主机静态检查不在本层复制。

未知版本、未知类型、错误方向、坏 CRC 或非法格式均丢弃，不生成逐条错误确认。传输层可累计所属诊断，后续有效消息仍可处理；不能据此刷新心跳、当前数据时间或共同指令缓存。合法的查询／维护请求被业务处理后仍可得到数据不可用或未开始的结果，这与格式错误不同。

## 3. 消息目录

H 表示主机，F 表示固件。下表 P 为载荷长度，完整长度均另加8。请求中的 `query_id` 和维护键只用于所属数据／结果会话。

| type（十六进制） | 名称 | 方向 | P | 完整输入或输出定义 |
|---|---|---|---:|---|
| 01 | Position | H→F | 4 | 绝对位置 `f32`，mm |
| 02 | Velocity | H→F | 4 | 线速度 `f32`，mm/s |
| 03 | Force | H→F | 4 | 推拉力 `f32`，N |
| 04 | Impedance | H→F | 12 | 平衡位置、刚度、阻尼，依次三个 `f32`；mm、N/mm、N·s/mm |
| 05 | Stop | H→F | 0 | 无参数 |
| 06 | Heartbeat | H→F | 0 | 无参数，只有这种消息更新实际入口联系 |
| 10 | Query | H→F | 5 | `query_id:u32, category:u8` |
| 11 | ReadConfig | H→F | 5 | `query_id:u32, view:u8` |
| 12 | ReadResult | H→F | 40 | `query_id:u32, key:36` |
| 20 | SaveConfig | H→F | 37..16420 | `key:36, record:bytes[P-36]`，完整候选1..16384字节 |
| 21 | RestoreFactory | H→F | 36 | `key:36`，采用当前固件配套且由主机核对的完整出厂记录 |
| 22 | ResetApplication | H→F | 36 | `key:36` |
| 23 | EnterUpdate | H→F | 36 | `key:36`；请求平台已经提供的应用更新入口，无镜像数据 |
| 24 | ReleaseResult | H→F | 40 | `key:36, revision:u32` |
| 80 | Telemetry | F→H | 152 | 第5节；`query_id=0` |
| 90 | Identity | F→H | 100..520 | 第6节，对应 Query category=0 |
| 91 | Status | F→H | 152 | 与 Telemetry 完全相同的载荷布局；`query_id≠0` |
| 92 | Measurements | F→H | 100 | 第7节，对应 Query category=2 |
| 93 | Diagnostics | F→H | 36..1060 | 第8节，对应 Query category=3 |
| 94 | ConfigData | F→H | 48..16432 | 第9节，对应 ReadConfig |
| 95 | OperationResult | F→H | 88 | 第10节，维护进展、已留存结果或未开始事实 |
| 96 | DataUnavailable | F→H | 48 | 第11节，读取或结果会话不可用的事实 |

`Query.category`：0对象身份，1当前状态，2详细测量，3详细诊断。保护参数通过启动配置视图取得，当前限制及保护事实由 Status/Telemetry 和 Diagnostics 表达；不存在另一份限值参数表。`ReadConfig.view`：0出厂、1实际用户记录、2启动配置、3当前通信设置。其他选择值非法。

四种目标的偏移均从载荷0开始，单值占0..3，阻抗依次占0..3、4..7、8..11。单位、完整目标、零值、持续与 Stop 的业务含义见[SDK README](../../README.md#公共交互与结果)；线上编码不钳位输入。不提供隐含字段、当前模式补全、目标持续时间或目标身份。Stop/Heartbeat 携带任意额外字节均非法。

查询标识为非零 `u32`，由同一调用方在同一设备应用会话内递增且不复用；耗尽后不能回绕复用未消歧的标识。初次身份查询可以尚不知道应用会话；之后主机将每个查询与已核对 UID、运行实例及所选类别绑定，丢弃不相符的回复。发送新查询不证明前一查询被取走；只读重查使用新的 query_id。查询数据副本在请求被取走后取得，不是收到首片时的状态。

## 4. 运行实例、快照和通用字段

### 4.1 运行实例与共同响应头

固件在每次应用启动生成新的非零128位 `run_nonce`；同一应用运行内固定。它不是用户身份、控制权或密码学认证。UID、固定初值、复位后归零的时间／计数器不能替代随机来源。生成失败时 `run_nonce` 全0并在身份/诊断中表达不可取得，不能把该值作为可用维护会话或跨启动数据依据。

所有 F→H 消息的载荷均以以下32字节 `sample` 开始：

| 载荷偏移 | 长度 | 字段 | 含义 |
|---|---:|---|---|
| 0 | 4 | `query_id` | Query/ReadConfig/ReadResult 的对应标识；周期遥测和原维护请求产生的进展/结果为0 |
| 4 | 16 | `run_nonce` | 本次应用运行实例，按字节顺序传递 |
| 20 | 4 | `snapshot_sequence` | 每次形成公开副本递增的计数，允许模2³²回绕；只作同一发布识别，不作时间或业务身份 |
| 24 | 8 | `snapshot_time_us` | 本次应用启动后单调微秒，`0..2⁶⁴-2`；全1保留，不编码墙钟 |

一次跨帧发送固定使用一份已形成的 sample 和数据。重新查询可形成新副本，重发同一副本不能改时间、来源年龄或序号。主机取得时间在主机本地记录，不进入以上字段。序号回绕比较仅在差值小于2³¹且 run_nonce 相同的连续观察中有意义；不足以消歧时重新查询身份和状态。

`age_us:u32` 表示来源取得时刻相对 snapshot_time_us 的年龄；0是确有同刻来源，`0xFFFFFFFF`是没有可用来源时间，`0xFFFFFFFE`表示年龄至少4294967294微秒，其他值为精确微秒。编码时按原来源时间计算；接收和转发不把年龄重置。接收方不能用饱和年龄恢复精确来源时刻；跨主机时钟只增加自己实际等待的年龄下界，不宣称已经精确校时。

### 4.2 数值状态与公开原因

每个观测 `value:f32` 配套一个 `value_state:u8`：

| 位 | 定义 |
|---|---|
| 0..2 | 数值结果：0从未有值；1可表示值；2换算/计算失败；3历史不足；4本次未计算；5输出禁止；6模型/参考不适用；7保留 |
| 3..4 | 来源质量：0未知；1合格；2来源故障；3连续性中断 |
| 5 | 过期事实：1表示所有者按适用年龄规则已判断过期；0不表示必然新鲜，仍看来源和年龄 |
| 6..7 | 保留0 |

结果非1时 `value` 必须为位模式 `00000000`，这是无值的占位，不是可用零测量；结果为1时保留实际有限值，即使来源已故障、已过期、为负或越界。结果0时年龄须全1；其余不可用状态可以保留导致失败的输入来源时间。可信越限只改变独立的限制/保护事实，不改变结果1或来源合格。可用且合格的典型 state=`09`，可用但已过期=`29`，历史不足且来源合格=`0B`。

`blockers:u32` 和 `reason:u16` 使用同一原因目录：bit k 对应数值为k+1的reason（下表reason列以四位十六进制书写）。blockers 可同时置多位；reason只表达该记录的单一主要原因，多个原因用多条诊断或多个bit，不按优先级互相覆盖。0表示没有该类原因。

| k（十进制）/ reason（十六进制） | 含义 | k（十进制）/ reason（十六进制） | 含义 |
|---|---|---|---|
| 0 / 0001 | 本入口未收到显式心跳 | 1 / 0002 | 本入口联系过期 |
| 2 / 0003 | 位置数值不可用 | 3 / 0004 | 位置过期 |
| 4 / 0005 | 线速度不可用 | 5 / 0006 | 完整压力对不可用 |
| 6 / 0007 | 压力对过期 | 7 / 0008 | 所需估算力不可用 |
| 8 / 0009 | 驱动状态不可用 | 9 / 000A | 驱动状态过期 |
| 10 / 000B | 驱动报告轴错误 | 11 / 000C | 轴状态不适用 |
| 12 / 000D | 等待本次进入证据 | 13 / 000E | 等待本次退出结清 |
| 14 / 000F | 已开始副作用未明 | 15 / 0010 | 维护资源占用 |
| 16 / 0011 | 操作输入无效 | 17 / 0012 | 目标超允许域 |
| 18 / 0013 | 控制计算失败 | 19 / 0014 | 硬保护条件 |
| 20 / 0015 | 会结束目标的软保护条件 | 21 / 0016 | 最终输出不合法 |
| 22 / 0017 | 所需资源不可用 | 23 / 0018 | 启动参数派生失败 |
| 24 / 0019 | 当前目标属于另一入口 | 25 / 001A | 没有当前目标 |
| 26 / 001B | 维护结果容量占用 | 27 / 001C | 无应用更新路由 |
| 28 / 001D | 运行实例来源不可用 | 29 / 001E | 测量参考不适用 |
| 30 / 001F | 来源明确故障 | 31 / 0020 | 保留，必须为0 |

此外单一 reason 定义：`0100`传输格式错误，`0101`组装超时，`0102`连接阶段改变，`0103`总线不可用，`0104`发送接口失败，`0105`接收容量溢出，`0106`控制周期遗漏；`0200`配置为空，`0201`配置残缺/不可解析，`0202`配置格式版本不支持，`0203`目标类型不能表示，`0204`存储读取失败，`0205`存储替换失败，`0206`读回不一致；`0300`结果未留存，`0301`操作标识已使用，`0302`设备不匹配，`0303`应用会话不匹配，`0304`结果尚未结清，`0305`结果版本已变化，`0306`结果已释放，`0307`所需信息不可取得。本段四位数值均为十六进制；其余保留，不直接传内部 Rust enum 的 discriminant。

`next_actions:u16` 为可组合的必要操作说明：bit0重新查询事实，1维持/重建所选入口心跳，2满足条件后提交新目标，3使用者明确停止，4实际读取用户记录，5主机核对完整配置，6另行请求应用复位，7采用外部更新/恢复路径，8处理外部设备条件，9取得并释放已结清维护结果，10等待已开始操作的事实，11..15保留。它是事实所有者给出的处理条件，不授权工具自动发出控制或副作用操作。

target_mode=0要求target_ingress=0；其他模式要求入口1或2。没有状态来源时driver_state bit0=0、raw字段全0且driver_age全1；这些零不能解释为驱动Idle或无错误。driver_state的来源合格与来源故障两位不得同时置位；bit0=0时其余位也为0。联系状态0的年龄为全1，其余必须有实际时间。资格掩码和输出允许位反映运行决策，不由主机从轴状态或心跳自行重建。模式专属输入是否允许仍取决于提交的完整参数及当时运行事实。

limits表示决策所有者当前仍有效的命中/保护事实，不能从单次测量越界自行清除。位置软限可以保持目标；其他限制是否结束目标由[SDK README 的公共交互与结果](../../README.md#公共交互与结果)以及 Status/Telemetry 的 `last_end_reason`、阻止掩码和输出资格共同表达。详细记录包含发生时刻、受影响量和解除条件。主要估算力固定来自滤波A/B对；正力通道和有效面积从启动配置读取，详细测量同时带所使用的模型事实。

## 8. 诊断和详细操作事实

Diagnostics 载荷为 `sample:32, count:u16, overflow:u8, reserved:u8, entries:64×count`，count=0..16。overflow=1表示同一副本还有未逐项列出的诊断，0表示已完整列出，其他非法。其存在不清除当前阻止掩码或必要维护结果；超过16项时先保留当前仍影响控制/资源的事实，其余以确定的 `(domain, object, reason)` 升序截取。不得用丢弃的历史记录替代当前事实。

## 9. 配置内容、视图与实际读回

完整配置格式及所有字段由 [`eha-config`](../../crates/config/README.md)和其[`schema.json`](../../crates/config/schema.json)唯一维护。实际产品出厂记录不属于本公开仓，也不拥有格式或字段规则。本协议不复制字段清单、参数范围或静态关系，不把Flash分区头、擦除对齐填充等写入应用配置字节。候选是配置所有者接受的完整JSON字节串，最多16384字节；本层不压缩、不解析后重序列化再冒充原候选。

ConfigData 固定前缀48字节：

| 载荷偏移 | 长度 | 字段与规则 |
|---|---:|---|
| 0 | 32 | sample |
| 32 | 1 | view：0出厂；1实际用户记录；2启动配置；3当前通信设置 |
| 33 | 1 | record_state：0完整可解析；1空；2残缺/不能解析；3配置格式版本不支持；4数值表示失败；5读取失败；6所需视图不可取得 |
| 34 | 1 | startup_source：0不可取得；1用户；2出厂，表示本次启动选源，不表示这次读回内容来源 |
| 35 | 1 | fallback_reason，与Identity定义相同 |
| 36 | 4 | data_length=N，0..16384，P必须等于48+N |
| 40 | 8 | data_time_us：实际读取或取得该视图副本的单调时间；不可取得为全1 |
| 48 | N | data，按view解释 |

view=0返回配套出厂记录原字节；view=1通过实际用户存储读回取得至多16384字节前缀，按 `Readback::json_bytes` 的定义只去掉末尾连续擦除态 `FF`，保留其余原字节，包括JSON空白、残缺和无效UTF-8；view=2使用配置所有者编码本次实际采用的完整参数，不伪装成原用户文件逐字节副本。view=0/2取得成功时state=0；view=1允许state=0..4且仍返回实际字节。state=1时N=0；state=2..4不得用出厂或候选数据替代。state=5/6时N=0且data_time全1。完整读取但不能解析与无法读取必须分开。

view=3成功时N=20，data依序为 `active_can_node:u32, profile:u8, reserved:bytes[3], host_heartbeat_hz:u32, telemetry_hz:u32, host_contact_max_age_ms:u32`，编码与Identity相同；这是实际设置投影，不是第二份可写配置格式。成功时state=0；其他仅允许5/6及N=0。

SaveConfig 的完整record交给配置所有者，解析失败在访问存储前形成未开始结果；结构合法而静态业务非法的记录仍可能按现有业务规则被保存，本协议不新增静态检查。RestoreFactory 无候选载荷，主机事先读取、检查同设备配套出厂记录；通过维护许可后由配置所有者将该完整内容写入用户记录，不删除用户区来代替恢复出厂。

OperationResult只陈述固件实际步骤，主机必须另用ReadConfig(view=1)取得同设备实际字节，与已保留候选逐字节比较。CRC相同不能替代完整比较。主机可以在本地报告“同设备保存读回一致”，不通过发送一个声明让固件把未取得证据改成成功。ReleaseResult不表示读回通过。本次参数不随保存改变；另行启动后用Identity和启动视图核对生效。

## 10. 维护结果会话

### 10.1 键、容量与副作用前预留

`key`固定36字节：偏移0 UID的12字节；12 run_nonce的16字节；28 `operation_id:u64`。UID和nonce必须对应同一当前控制器、当前非零运行实例；operation_id为非零、同一应用会话内由唯一串行调用方严格递增的标识。它只定位维护，不能用于控制目标、片段或伪造实际入口。

固件为CAN/USB合计保留 **一个维护结果槽** 和一个u64的已处理操作标识上界H，初始H=0。槽保存操作、涉及内容的长度/CRC、阶段、证据、原期限、影响和结果版本。CRC用于指认内容，主机仍保留完整候选完成实际比较。

处理SaveConfig/RestoreFactory/ResetApplication/EnterUpdate时：

1. 请求必须已经按公共规则完整交付并从共同缓存取走；未取走不推定产生会话或推进H。
2. 先核对UID、非零nonce。对象不符或运行实例不可取得时不产生本次副作用，返回所属维护不可用事实，不改变H或旧结果。
3. `operation_id≤H`绝不重做副作用：正好等于留存槽时只返回原槽快照，不把重复请求的不同操作/载荷认作已执行；否则返回DataUnavailable(reason=0301)。不提供自动重放机制。
4. `operation_id>H`在处理该申请时推进H，即使随后因格式、许可或结果容量不足而未开始也消费该标识。调用方必须先查事实，确需重新提出时使用新的更大标识；H不得回绕。
5. 结果槽可用时，许可、必要资源占用和结果预留作为同一步完成。解析及许可拒绝可留存为NotStarted；只有预留完成才能开始副作用。槽占用时不覆盖旧结果，新申请返回一次非留存NotStarted(reason=001B)，并在Status中保留容量占用事实。

上述非留存通知仍是维护请求被处理后的结果说明，不建立可重取会话，不承诺送达。任意连续拒绝不能要求无限内存；新请求即使通知丢失，也不能因此在旧标识重传后开始。H只说明标识已消费，不证明其副作用开始或成功。调用方重新打开访问后先读取Identity中的H和retained_operation_id，核对原留存结果；新申请只能使用大于H的标识，不从1重新计数或猜测旧操作结果。

| 3 固件步骤完成 | 仅操作1/2；phase=7/8/11；evidence的替换成功bit1及已结清bit5必须为1，未开始bit0和原结果缺失bit4必须为0 | started/finished有时间且有序；revision非0；constraints仅bit3；不代表主机已取得或比对读回 |
| 4 已失败 | phase与实际失败阶段相符（1/6/7/8/10/11）；reason非0；已结清bit可为0或1，不能因错误返回就清除未明资源 | started有时间；已结清时finished有时间且constraints仅bit3，否则finished全1；revision非0 |
| 5 等待到期 | reason非0、已结清bit=0；保留实际phase，不能改作未开始 | started/deadline有时间，snapshot_time达到deadline，finished全1，revision非0，保留实际constraints |
| 6 结果未明 | reason非0、已结清bit=0，evidence bit3或bit4至少一个为1；保留原阶段和实际影响 | started有时间，finished全1，revision非0，constraints至少含结果槽及相关受约束资源 |
| 7 应用移交已开始 | 仅操作3/4，phase=10，evidence bit3=1；bit0/1/2/5为0 | started有时间，finished全1，revision非0，constraints含应用移交及结果槽；不能表示新应用或DFU已经出现 |

已知的started和finished必须不晚于snapshot_time；finished不得早于started（未开始结果没有started）。有deadline时不得早于started，但尚未到期的deadline可以晚于snapshot_time。操作1/2的实际执行阶段限于6/7/8/11，操作3/4限于1/10/11；条件检查阶段1也可返回未开始。操作3/4的存储证据bit1/2始终为0。evidence bit0不得与bit1/2/3同时为1。除state=0非留存通知外revision不可为0，活动/留存槽的constraints始终含bit3；time=全1只表示上述允许的“不适用/尚未取得”，不能用0冒充未知。返回失败但已确认存储现状、资源也已结清时可置已结清bit；结果未知不能仅因主机读到当前内容就改成原步骤完成。

state=3只表示固件所属步骤有完成证据；保存通常表示存储替换返回成功，仍须实际读回和主机比对。state=4可与“副作用可能已发生”并存，不等于未执行。state=5/6时不得置已结清bit；原期限保持，迟到的新事实只能按原操作完成条件更新结果，不重新开始操作。结果版本不得回绕；理论耗尽时保持结果不可释放并报告资源不可用，不复用旧版本。

ReadResult是只读，明确键后任一入口可查询同一槽，回复走本次查询入口；不存在或已释放时返回DataUnavailable(reason=0300/0306)，绝不把“无记录”改成“未执行”。原申请入口的发送进度不改变业务结果。通信恢复只清传输组装，不能清结果槽、H或未明影响。

ReleaseResult也是共同缓存中的完整用户指令，仅在键及revision精确匹配、state为0/3/4、已结清bit=1、约束只剩结果槽时释放。进行中、等待到期、未知、应用移交或仍受资源约束时不释放；返回OperationResult原事实或DataUnavailable相应原因。释放后ReadResult以新的query_id查询可确认结果不再留存；ReleaseResult不需要业务逐条确认。主机只有已经取得并处理该终态，才请求释放；未被取走的释放不生效，发送成功不代表槽已回收。

释放不更改H、原存储、控制目标、心跳或设备状态，不可作为取消/清错。不按经过时间、通信断连或本地回复提交自动回收已开始操作结果。仅保留一个最近释放的operation_id用于返回0306；更旧且不在槽中的标识返回0300，仍由H阻止重做。

应用复位和更新切换是会结束应用会话的操作：通过许可即可以执行，不依赖回复形成、提交或主机取得。state=7只表示应用移交已经开始，不表示实际复位/进入DFU。应用结束后不承诺保留旧槽或H，也不要求先ReleaseResult。主机须核对同一UID的新应用nonce、版本和启动配置，或交付约定的外部更新入口身份；预期断连不能替代这些证据。

## 11. 数据不可用

DataUnavailable 的P=48：`sample:32, subject:u8, reason:u16, next_actions:u16, retained:u8, reserved:bytes[2], operation_id:u64`，依次偏移32、33、35、37、38、40。

subject=0身份、1当前状态、2测量、3诊断、4配置、5维护结果、6结果释放。retained=0没有可返回的留存结果、1仍保留原结果；其他非法。与维护无关时operation_id=0。字段足以解释数据不可取得或会话失配，不充当控制命令拒绝确认。一般查询的query_id必须非0；维护原申请或ReleaseResult引起的事实可为0。

对象不匹配时响应携带本机的运行实例，主机不得归并到原设备。没有回复只表示未取得结果；不生成一条虚构的DataUnavailable，也不能据此改变控制或自动重发副作用。

## 12. 传输期限

CAN 与 USB 绑定分别规定从首片开始的绝对组装期限：短消息20 ms，大消息30 s；期限不会因后续片段延长。它们不是主机联系年龄、设备操作期限或主机调用总等待。组装超时、格式失败或阶段变化都不产生业务消息；只读查询可以重新发起，目标和副作用必须由使用者重新表达意图，绑定不得自动重放。

## 13. 可复算样例与失败场景

以下样例使用本合同版本和CRC，十六进制串中的空格/换行仅用于阅读。第13.1节的短消息是完整线上字节；第13.2节提供独立可执行的生成规则，完整配置输入直接引用其唯一所有者，不在本文复制一份字段表或大段十六进制。

### 13.1 短消息

下列均包含4字节公共头、完整载荷和4字节CRC；对应第13.2节生成规则。

| 消息 | 完整字节（十六进制） |
|---|---|
| Position 10 mm | `01 01 04 00 00 00 20 41 AF A9 79 D3` |
| Velocity −2 mm/s | `01 02 04 00 00 00 00 C0 8E 87 6A 64` |
| Force 0 N | `01 03 04 00 00 00 00 00 82 8D E4 CF` |
| Impedance（50 mm，10 N/mm，2 N·s/mm） | `01 04 0C 00 00 00 48 42 00 00 20 41 00 00 00 40 99 C2 F1 59` |
| Stop | `01 05 00 00 1B D7 BD AE` |
| Heartbeat | `01 06 00 00 68 17 93 44` |
| 读取实际用户记录，query_id=8 | `01 11 05 00 08 00 00 00 01 F3 AB 7E 78` |

### 13.2 独立生成与解码核对

下列 Python 仅使用标准库，可从仓库根运行；输出每条完整消息的长度、CRC 和十六进制，包括完整配置保存、实际读回和结果查询。输入为公开测试夹具 `tests/fixtures/config.json` 的原始字节，不经 JSON 重排；字段与格式仍归配置所有者。本例使用固定 nonce `01..10`、UID `01..0c` 作为测试数据，不作为设备生成规则。

```python
from pathlib import Path
import struct

def crc32c(data):
    c = 0xffffffff
    for x in data:
        c ^= x
        for _ in range(8):
            c = (c >> 1) ^ (0x82f63b78 if c & 1 else 0)
    return c ^ 0xffffffff

def message(kind, payload=b''):
    assert len(payload) <= 16432
    head = struct.pack('<BBH', 1, kind, len(payload))
    body = head + payload
    return body + struct.pack('<I', crc32c(body))

assert crc32c(b'123456789') == 0xe3069283
uid, run = bytes(range(1, 13)), bytes(range(1, 17))
key = uid + run + struct.pack('<Q', 1)
def sample(query_id, sequence, time_us):
    return struct.pack('<I', query_id) + run + struct.pack('<IQ', sequence, time_us)
out = {
    'position_10mm': message(1, struct.pack('<f', 10)),
    'velocity_minus_2': message(2, struct.pack('<f', -2)),
    'force_zero': message(3, struct.pack('<f', 0)),
    'impedance': message(4, struct.pack('<fff', 50, 10, 2)),
    'stop': message(5),
    'heartbeat': message(6),
    'read_measurements': message(0x10, struct.pack('<IB', 9, 2)),
    'read_user': message(0x11, struct.pack('<IB', 8, 1)),
    'read_result': message(0x12, struct.pack('<I', 10) + key),
    'release_result': message(0x24, key + struct.pack('<I', 3)),
}
# 位置可信但越界仍报101mm；速度历史不足；滤波B失败导致主要力无值。
# 原换算A/B仍可用，保护估算力仍如实为188.5N。
values = struct.pack('<8f', 101, 0, 1, 2, 1, 0, 0, 188.5)
states = bytes([9, 11, 9, 9, 9, 10, 10, 9])
measurement = (sample(9, 7, 1000000) + values + states + struct.pack('<IIIIf',
               100, 100, 200, 10000, 188.5) + bytes([2, 1, 1, 0])
               + struct.pack('<I', 20))
assert len(measurement) == 100
out['measurements_mixed_availability'] = message(0x92, measurement)
record = Path('tests/fixtures/config.json').read_bytes()
assert 0 < len(record) <= 16384
out['save_complete_config'] = message(0x20, key + record)
out['actual_user_readback'] = message(0x94, sample(8, 8, 1001000) + bytes([1, 0, 2, 1])
                                     + struct.pack('<IQ', len(record), 999000)
                                     + record)
# 保存调用完成、结果已结清，但尚无主机完整读回核对结论。
result = (sample(10, 9, 1002000) + struct.pack('<QBBBBHHIQQQIII',
          1, 1, 3, 7, 0x22, 0, 0x10, 8,
          800000, 0xffffffffffffffff, 900000,
          len(record), crc32c(record), 3))
assert len(result) == 88
out['write_returned_result'] = message(0x95, result)
for name, msg in out.items():
    p = int.from_bytes(msg[2:4], 'little')
    assert len(msg) == p + 8
    assert int.from_bytes(msg[-4:], 'little') == crc32c(msg[:-4])
    print(name, 'length=', len(msg), 'crc=', msg[-4:].hex(), msg.hex(' '))
```

### 13.3 必须区分的失败

| 输入或场景 | 应有结果 |
|---|---|
| 正确Position只收到前11字节 | 没有完整消息，直到绑定期限；不能更新缓存 |
| P=16433或实际数据长于声明L | 超过全局上限或多余尾部，拒绝；不能只解合法前半部分 |
| version=2，即使重新计算了正确CRC | 未知版本，拒绝；不能当版本1 |
| type=07、错误方向或保留位非0且CRC正确 | 格式非法，丢弃，无逐条错误确认 |
| Impedance只有平衡位置/刚度 | 长度非法，不继承旧阻尼 |
| 目标f32位模式7FC00000或7F800000 | NaN/Infinity表示非法；不变成零目标 |
| 完整Position在软范围外 | 编解码可交付，运行决策判断不采用，保留当前目标；与格式失败不同 |
| 实际用户记录只有一个左花括号或全FF | 返回真实残缺字节或空记录事实；不得要求“读回必须解析成功” |
| 旧头与另一副本尾部混合 | 传输归属/顺序检查或公共CRC拒绝，不能拼出混合观测 |
| 首片后超过绑定绝对期限 | 废弃组装，不刷新心跳；后来片段不能复活原组 |
| 跨连接旧片段后接新消息 | 旧组不可续接，新阶段只从合法首片建立；见两个绑定的清理矩阵 |
| 保存已开始而回复截断/断连 | 不清维护结果；查询原key或实际读回，不重发保存 |
| ReleaseResult被后续查询覆盖 | 原槽继续留存，不按发送成功回收 |

软件样例只证明对应编码、长度和算法，不能证明接入硬件、总线裕量或业务任务已经实现。
